# IdeaLab

个人创意实验室：统一记录灵感、研究、实验与项目决策。每个创意项目在 `ideas/` 下拥有独立目录。

> **强制协作约定**：IdeaLab 的所有子项目，无论是创意探索、技术研究、动画制作还是软件开发，都必须采用独立 **AI-Workflow** 框架的适用流程。AI-Workflow 虽然独立版本管理，但不是可选的项目附件。新会话、接手者或新里程碑开始时，先阅读本仓库总规则，再阅读目标项目资料，最后加载该项目指定版本的 AI-Workflow 规范。

## AI-Workflow 强制协作规范

### 两个仓库，各司其职

- **IdeaLab（本仓库）**：保存创意、子项目资料、已批准的决策、里程碑与成果链接。
- **AI-Workflow（独立 Private 仓库）**：保存通用生命周期、动态组队、内部辩论、Skills/工具适配、质量审查、回退和里程碑审批规范。
- **各子项目**：保留各自业务事实与成果；需要代码仓库或大型素材库时，可在项目文档中链接外部仓库。

当前默认版本为 [AI-Workflow V1.0](https://github.com/VJ-VickWeijie/AI-Workflow/tree/76f2d0ab04ff5b2d8d0920699372a79dca69337c)。项目可在自身资料中指定另一个已批准的固定提交。

### 必须遵循的启动顺序

1. **读取 IdeaLab 总规则**：本 `README.md` 和根目录 `AGENTS.md`。
2. **读取目标子项目**：`ideas/<项目>/README.md`、已批准的需求/决策、当前里程碑及相关成果；不得用其他项目资料替代。
3. **读取 AI-Workflow**：解析该项目指定的工作流版本，读取对应流程、角色、权限、质量和交接规范；不能访问时停止正式执行并报告。
4. **恢复上下文与授权**：核对当前阶段、上次审批、任务范围、风险、可用工具和权限。
5. **阶段内自治**：动态组建专业团队，自行选择授权范围内的 Skills 与工具，完成讨论、交叉批判、任务拆分、执行、独立审查和普通返工。
6. **里程碑验收**：提交成果、证据、争议、风险与下一阶段建议，等待项目所有者批准后进入下一重大阶段。

完整执行约定见 [AI-Workflow 接入规范](docs/AI_WORKFLOW_INTEGRATION.md)。

### 通用生命周期

`M0 目标探索 → M1 多角色评审 → M2 专业方案设计 → M3 实施规划 → M4 自主执行 → M5 独立验收 → M6 交付复盘`

项目可以按规模合并或细分阶段，但不得跳过必要的质量检查和人工审批。不同项目使用不同专业角色与产出：软件可使用 PRD、规格、实施计划；动画使用剧本、分镜、素材与成片验收；研究使用证据、实验与结论。

**人工审批边界**：每个主要里程碑结束时由项目所有者决定批准、修改重审、暂停或终止。阶段内部普通决策由 AI Team 自主处理。重大目标变化、额外成本、敏感/不可逆操作或授权不足时须提前请示。

### 工作流版本与不可用情况

每个子项目应记录所采用的 AI-Workflow 版本或固定提交。工作流升级不自动改变进行中项目的已批准范围。若工作流仓库无法访问、版本不明、必要资料缺失或工具不可用，应如实报告，**不得声称已加载 Skills、完成独立审查或执行测试**。

## 新建创意

复制 [统一创意模板](templates/IDEA_TEMPLATE.md) 到 `ideas/<项目名>/README.md`，先写灵感卡，再将项目链接加入上面的索引。新建创意可先记录，不代表已获批准进入执行阶段。进入调研、验证或开发时，按上述启动协议采用 AI-Workflow。

### 用 ChatGPT 记录

> 帮我把这个新点子记录到 IdeaLab（VJ-VickWeijie/IdeaLab）。想法是……

这句话表示可以直接整理并提交到 GitHub。项目名可选，只有一句描述也可以先记录。创建项目时，在 `ideas/<项目名>/README.md` 写入灵感卡，并把项目加入索引。

要补充已有项目，可以说「把下面这条补到 IdeaLab 的 Marble 项目里」。想先聊聊，可以说「先讨论这个点子」。
