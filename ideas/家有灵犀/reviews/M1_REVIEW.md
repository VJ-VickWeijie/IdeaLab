## 一、评审目标与范围

评估从零重启后的产品边界、单人模式定义、NAS 与 Android 的数据关系、LAN 和外网访问路线、首版功能范围及关键安全风险。形成进入 M2 的推荐方案与需项目所有者决定的事项。本阶段不实现 APK、服务端、数据库或网络隧道。

## 二、四个角色视角

### 产品与家庭数据

家庭模式应以家庭空间承载共享任务、购物清单和日程，由家庭主账号管理邀请与成员权限。私人待办属于具体账号，不应因为加入家庭而默认共享。

“单机/单人模式”有两种不同含义：

1. 不加入家庭空间的个人账号，数据仍保存于 NAS。
2. 不依赖 NAS 或网络的纯本地模式，数据保存在手机。

推荐 V1 先定义为第一种，叫“个人空间”或“单人空间”。它与家庭空间是并列的数据工作区。两者共用 NAS 服务端和账号基础设施。纯本地模式、个人空间转家庭空间及跨空间数据合并留到后续版本设计。这最符合 NAS 作为家庭数据中心的方向，也避免首版同时实现两套存储和同步体系。

历史 PRD 中“私人待办”与“单人模式”要区分。私人待办是家庭成员账号内仅自己可见的任务。个人空间是不需要家庭成员关系的独立工作区。

### Android 客户端

客户端应持有本地数据库缓存和服务端 API 两类数据源。界面从本地数据读取，客户端联网时由数据层同步服务端结果。MVP 建议在 NAS 不可达时提供已有数据的只读查看，暂不允许离线编辑，避免冲突策略、重复写入、成员间并发修改及数据丢失问题。未来增加离线写入时需定义队列、冲突解决、重试和同步状态。

Android 官方离线架构建议使用本地数据源支撑离线读取，并由 repository 协调网络与本地来源。它支持“NAS 主数据 + 手机缓存”的方向，但具体缓存字段、过期策略和同步规则要在 M2 设计。见 [Android 官方离线优先架构](https://developer.android.com/topic/architecture/data-layer/offline-first)。

### NAS 服务端

服务端应作为唯一权威业务写入入口。APK 只访问服务端 API，不直连数据库。家庭权限必须在服务端对每次请求验证，不能只靠客户端隐藏按钮。每个工作区的数据隔离、账号认证、权限检查、审计、备份和恢复应作为 M2 的关键设计点。

项目早期可以比较单个 API 服务加关系型数据库的方案。此前讨论的 ASP.NET Core 与 PostgreSQL 尚未获得本轮批准。若继续考虑 .NET，不能沿用 .NET 8 作为新部署基线。微软当前支持表显示 .NET 8 于 2026-11-11 结束支持，.NET 10 为 LTS 并支持至 2028-11-14；M2 应优先评估受支持的 .NET 10 LTS，也应根据 NAS 容器环境确认实际部署兼容性。见 [.NET 官方支持策略](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。

### 网络与安全

#### 局域网

在同一家庭网络内，APK 通过 HTTPS 连接 NAS 服务。M2 需设计首次配对/服务器地址配置、NAS 地址变化处理、证书信任和局域网离线提示。不能把 IP 地址发现、明文 HTTP 或证书忽略作为默认方案。

#### 外网候选 A：Tailscale 私有网络

在 NAS 和家庭成员手机安装并登录 Tailscale，通过私有网络访问 NAS，不需要开放路由器入站端口。Tailscale Serve 用于 tailnet 内共享服务，只有加入该网络的设备能访问。适合个人测试或家庭成员都能接受安装额外 VPN 客户端的私有访问。代价是每位成员需加入 tailnet、安装并维护额外客户端，Android 上也需处理与其他 VPN 的使用冲突。Tailscale Funnel 可公开暴露服务，官方仍标为 beta，本项目不建议把它作为长期家庭 API 的默认入口。见 [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)、[Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel)。

#### 外网候选 B：Cloudflare Tunnel + 自有域名

在 NAS 运行 `cloudflared` 建立从家庭网络向外发起的连接，Cloudflare Tunnel 支持无公网 IP 且无需开放入站端口的服务访问。可以使用自有域名，但域名需处于 Cloudflare 可用的 DNS 配置中，必要时需切换 DNS 托管或配置部分 CNAME。它能让家庭成员直接用 APK 和域名访问 API，不要求所有手机先加入私有 VPN，更贴合“公网网络下直接联网”的体验。

风险是 API 会成为互联网可达服务，隧道本身不替代账号认证、工作区权限、限速、更新和安全日志。Cloudflare 官方明确说明，发布自托管应用时应先配置 Access，否则 tunnel route 可能对公网开放；还建议在源站验证 Access token，避免绕过代理的请求被接受。对原生 Android API，需要在 M2 验证登录与 Access 身份流程是否能和 APK 顺畅配合。见 [Cloudflare Tunnel 原理](https://developers.cloudflare.com/tunnel/concepts/) 和 [发布自托管应用的安全配置](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)。

#### 推荐的外网方向

推荐把 Cloudflare Tunnel 作为首选评估路线，以自有域名提供 HTTPS API，并保留服务端自己的家庭账号认证和授权。公网只暴露应用 API，不暴露 NAS 管理页面、Docker 管理或数据库端口。若原生应用身份验证、域名 DNS 管理或 Cloudflare 账户配置不符合用户实际情况，则回退评估 Tailscale 私有网络。M2 必须做可行性验证后才能批准具体部署方案。

Cloudflare Tunnel 的工作方式是由 NAS 连接 Cloudflare，免去路由器入站端口配置，但公网请求仍会经过第三方网络服务。用户需要在 M2 确认是否接受该外部依赖。此建议不代表已部署隧道或现有域名已接入 Cloudflare。

## 三、M1 推荐方案

| 议题 | M1 推荐 | M2 待明确 |
| --- | --- | --- |
| 产品模式 | 家庭空间 + 独立个人空间，共用 NAS 服务端 | 是否接受“单人模式不等于纯本地模式” |
| 主数据位置 | NAS 服务端为权威来源 | 数据库与备份恢复方案 |
| 手机数据 | 本地数据库缓存，离线查看；首版不支持离线编辑 | 缓存范围、保留和清理策略 |
| 局域网连接 | APK 通过 HTTPS 访问 NAS API | 首次配对、地址发现和 TLS 证书 |
| 外网连接 | 优先评估 Cloudflare Tunnel + 自有域名；Tailscale 作为私有替代 | 域名 DNS 当前托管方、用户是否接受第三方隧道、原生 APK 鉴权 |
| API 安全 | 所有写入通过 API，服务端按家庭/个人工作区授权 | 认证方式、会话撤销、限流、日志 |
| 服务端技术 | 比较 ASP.NET Core + 受支持 .NET 与其他方案；若选 .NET 优先评估 .NET 10 LTS | UGOS/Docker 部署兼容、数据库、升级和备份 |
| 首发功能 | 先完成账号/空间、家庭成员、待办、购物清单、日程、首页和基本提醒 | 是否把模板放入首版，具体验收标准 |
| AI/语音/识图 | 建议延后到核心家庭功能稳定后，分别评估授权与本地/云端边界 | 用户是否同意分期上线，保留哪些首发语音功能 |

## 四、关键风险和控制方向

- **外网暴露风险**：不开放 NAS 管理端和数据库端口；隧道只路由到 API；任何外围 Access 机制之外仍有应用层账号认证与授权。
- **家庭数据误共享**：为家庭共享数据、个人空间数据、家庭成员私人待办分别定义归属和访问矩阵。
- **离线数据冲突**：MVP 离线只读；未来支持编辑前先建立同步队列和冲突策略。
- **NAS 故障与误删**：定义定期备份、异地副本和恢复演练。RAID 不当作备份。
- **长期技术支持**：部署运行时采用仍受支持的版本；.NET 8 已结束支持。
- **域名与第三方依赖**：确认域名 DNS 托管、隧道账户、费用与故障时的回退路径。
- **家庭成员使用门槛**：比较“每台手机安装 Tailscale”与“普通 APK 直接访问 HTTPS 域名”的体验差异。
- **额外云端处理**：语音、图片与 AI 内容上传之前提供清晰告知和主动触发，避免秘密自动上传家庭数据。

## 五、M1 决策建议

请项目所有者在批准 M1 时确认以下方向：

1. **个人模式含义**：是否同意首版“单人模式”定义为不加入家庭的 NAS 个人空间。纯手机本地模式作为后续方向。
2. **外网方向**：是否同意优先评估 Cloudflare Tunnel + 自有域名，并保留 Tailscale 私网访问为替代方案。
3. **离线范围**：是否同意首版断网只读本地缓存，暂不支持离线编辑。
4. **首发范围**：是否同意先交付家庭核心功能，把 AI 助手、语音和识图作为后续独立阶段评估。
5. **技术选择门槛**：M2 再确定数据库、后端栈、Android 架构和访问鉴权，不直接沿用旧项目选择。

若其中任何方向不符合用户原意，可在 M1 验收意见中修正。以上为建议，不是已经生效的产品决定。
