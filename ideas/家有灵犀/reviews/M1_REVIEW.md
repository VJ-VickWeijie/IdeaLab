## 一、评审范围

定义线上账号、家庭共享、开发测试本地模式、NAS 服务端和手机客户端之间的边界，评估后续局域网与互联网访问的候选路线，以及首版功能范围。本阶段不实现 APK、服务端、数据库或网络隧道。

## 二、项目所有者已澄清的产品模型

### 线上个人账号与家庭组

每个人都有自己的账号和个人数据。个人数据及家庭共享数据物理上都由同一套 NAS 服务端保存，不分成“个人数据存一处、家庭数据存另一处”。

家庭组是成员关系和共享权限机制。用户可以选择把具体内容共享给家庭组或其他成员。只有获准共享的内容能被其他成员查看或共同使用。家庭组不应自动让成员看到对方的全部私人数据。家庭主账号负责创建家庭组、邀请和管理成员。

因此，产品里的“个人账号/私人数据”与“本地单机测试模式”是不同概念。线上个人账号可加入家庭组，也可独立使用账号服务。家庭共享是对数据访问范围的授权。

### 本地单机测试模式

在联网账号版开发完成前，Android APK 可提供开发测试模式：

- 不要求登录账号，不连接 NAS 或互联网。
- 数据写入当前手机的本地存储，供单机功能测试。
- 本地测试数据与线上账号/NAS 数据互相独立，不假设自动同步。
- 本地测试模式可进行本地新增、修改和删除。线上模式遇到网络中断时的规则另行处理。

这一模式解决早期无法依赖 NAS 联网测试的问题。M2 应设计本地数据层与服务端数据层的接口，使核心页面和业务逻辑可逐步接入线上 API，避免先做本地版后整套推倒重写。

### 线上模式的断网行为

项目所有者确认线上模式断网时只读。Android 可以展示手机上已缓存的数据，但不能在无法连接 NAS 时修改线上数据。首版暂不做离线写入队列和冲突合并。在线恢复后再从 NAS 同步。此限制不禁止本地单机测试模式写入本机数据库。

Android 官方离线架构建议联网数据层保留本地数据源，最低限度支持离线读取，并由 repository 协调本地与网络数据。此指导支持“线上 NAS 权威数据 + 手机上的本地缓存”设计。见 [Android 官方离线优先架构](https://developer.android.com/topic/architecture/data-layer/offline-first)。

### 首版输入与功能范围

项目所有者已确认初期只需要文字录入。AI 助手、语音识别和识图列入后续阶段。首版候选核心范围为账号与家庭组、邀请与成员权限、待办、共享购物清单、日程、首页和提醒。历史 PRD 中的私人待办、单一共享购物清单、共享删除确认及可恢复记录等规则，在 M2 PRD 中逐项确认和写出验收条件。

## 三、四个角色视角

### 产品与家庭数据

服务端数据模型应明确个人账号、家庭组、家庭成员、私人数据和被共享的数据。家庭主账号管理成员关系，但数据可见性按明确权限和共享对象判断。加入家庭组不应自动把账号下所有私人内容公开。M2 应建立资源级访问矩阵，覆盖待办、清单、日程和操作记录。

个人账号的 NAS 数据与家庭组共享内容采用同一 NAS 存储和服务端，不引入两套持久化系统。共享是权限关系，数据归属、可见范围和删除/恢复记录应在业务模型中表达。

### Android 客户端

早期 APK 使用手机本地存储完成单机测试，不登录、不联网。线上账号模式使用本地数据库缓存，显示缓存内容，联网时与 NAS API 同步；线上断网只读。建议从第一阶段就把业务页面和数据访问接口分开，让本地数据源可先行开发，之后接入 API。

本地测试数据与线上账号数据分开保存、分别标注环境。避免测试操作误写真实家庭数据。具体测试数据清理、切换模式和线上缓存策略留到 M2。

### NAS 服务端

NAS 是所有线上个人账号和家庭组数据的统一存储及权威写入入口。APK 只通过服务端 API 操作数据，不直连数据库。服务端逐请求检查用户身份、资源归属和共享权限。账号隔离和显式共享关系是关键安全边界。

此前讨论的 ASP.NET Core 与 PostgreSQL 尚未成为本轮决定。若考虑 .NET，新部署应评估受支持版本。微软支持表显示 .NET 8 于 2026-11-11 结束支持，.NET 10 为 LTS 并支持至 2028-11-14。若选 .NET，M2 优先评估 .NET 10 LTS，并验证绿联 DXP4800 的容器运行兼容性。见 [.NET 官方支持策略](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。

### 网络与安全

#### 局域网

线上 APK 通过 HTTPS 访问 NAS API。M2 需确定首次设置服务器地址、NAS 地址变更、证书信任、连接失败提示和备份恢复。开发测试模式不依赖局域网。

#### Cloudflare Tunnel 是什么

可以把它理解为运行在 NAS 上的一个连接程序。NAS 主动向 Cloudflare 建立加密连接，外部手机访问域名时，Cloudflare 再把请求通过这条已建立的连接送到 NAS。它的作用是让没有公网 IP、没有路由器入站端口映射的家庭服务也能从互联网访问。官方文档说明 Tunnel 由内向外建立连接，无需向 NAS 开放入站端口。见 [Cloudflare Tunnel 原理](https://developers.cloudflare.com/tunnel/concepts/)。

代价是请求经过 Cloudflare，且域名需要在 Cloudflare 可用的 DNS 配置中。Tunnel 只负责连接路径，不自动等于账号登录或家庭数据授权。若公开 API，仍需应用自己的账号认证和资源级权限。Cloudflare 文档提示应先配置 Access，否则发布的自托管应用可能对互联网开放，并建议源站验证 Access token。原生 Android APK 如何顺畅完成 Access 登录仍需测试。见 [Cloudflare 发布自托管应用的安全配置](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)。

当前域名 DNS、NAS 和路由器配置均未检查。现阶段不要求选择 Cloudflare 或购买服务。M2/联网实施前再评估它与其他路线的适配性、费用、第三方依赖及使用体验。

#### 外网候选：Tailscale

Tailscale 是让家庭设备加入同一个私有网络的服务。NAS 和手机都加入后，成员可从外部通过私网访问 NAS。Tailscale Serve 面向同一 tailnet 里的设备；这通常要求每位家庭成员安装客户端并登录。见 [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)。

它适合只给家庭成员开放的私有访问。Cloudflare Tunnel 更接近“手机直接访问自有域名”的体验。Tailscale Funnel 可公开服务，但官方仍标为 beta，不作为本轮推荐的正式家庭 API 入口。见 [Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel)。

#### 外网方向

M1 不要求现在决定网络隧道。正式目标仍是家庭成员能从局域网和互联网访问 NAS 服务。Cloudflare Tunnel、自有域名和 Tailscale 是后续候选，待域名 DNS、NAS 和登录方式核对后在 M2 或联网上线前作具体选择。

## 五、风险与控制

- **误共享**：服务端按资源授权判断可见性，家庭组成员关系本身不直接授予查看全部数据的权限。
- **测试数据误入线上**：本地测试模式和线上账号模式隔离，UI 与数据层明确标识当前环境。
- **断网误写**：线上断网不允许修改；本地测试模式仍可写本机数据库。
- **公网暴露**：具体隧道路线确定后，仅发布必要 API，NAS 管理、容器管理和数据库不得对公网开放。任何代理层都不能取代应用认证与权限检查。
- **NAS 故障和误删**：M2 设计备份与恢复。RAID 不作为备份。
- **技术支持周期**：选择仍受支持的服务器运行时和基础镜像。
- **第三方依赖**：联网方案确定前核对域名 DNS、费用、外部服务依赖和故障恢复路径。
