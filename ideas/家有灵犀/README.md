# 家有灵犀

状态：重启中，当前处于 AI-Workflow V1.1 的 M0 目标探索，待项目所有者验收。

## 项目重启说明

本轮从零重新规划。此前的 APK、代码和技术实现不作为新项目的基础，也不安排迁移。历史 PRD 中已确认的产品需求可作为参考输入。此前材料仅作需求参考，不能自动视为本轮已批准的设计。旧 APK 与旧实现不在本轮维护范围内，本记录不执行删除操作。

## M0 项目目标（验收草案）

为用户及其家庭建立一个可安装到 Android 手机的家庭生活助手。家庭模式支持家庭主账号和多个家庭成员账号。产品同时支持单人独立使用。家庭业务数据以用户的绿联 DXP4800 NAS 为主要存储，由 NAS 上的服务端提供 API 和数据服务。

客户端目标是在家庭局域网内联网使用，并具备通过互联网访问家庭服务端的能力。用户拥有域名，但目前没有配置内网穿透或其他外网接入方式。外网访问方式尚未确定，不能视为已可从公网连接。后续需评估合适方案并明确安全、成本和可维护性。

最终交付目标包括 Android 安装包 APK、可在 NAS 部署的服务端，以及客户端和服务端的联网能力说明。M0 不预先决定技术栈、网络接入方式、认证实现或部署拓扑。

## 已提出的产品边界

- 家庭模式包含家庭空间、家庭主账号和多成员账号。
- 单人模式允许一个人独立使用，不要求先创建或加入家庭。
- 家庭数据主要存放在 NAS 长期运行的服务端。
- Android 客户端连接服务端访问和同步家庭数据。
- 用户明确表示此前 APK 可舍弃，新项目不继承旧代码和实现。
- 旧项目是否存在需要保留的业务资料、以及旧 APK 所在位置，尚未盘点。本轮不删除任何旧文件或仓库。

## 既有 PRD 参考

此前确认的需求可作为后续 M1/M2 的参考基线，需在新一轮评审中逐项复核：

- 创建家庭空间并邀请成员，支持权限与操作记录。
- 待办支持共享和私人任务，可设置负责人和截止日期。
- 普通成员可删除其他成员创建的共享任务，但需确认并保留恢复记录。
- 家庭购物清单第一版只有一份共享清单，支持数量、勾选和同步。
- 断网时购物清单仅离线查看，恢复联网后再编辑。
- 日程支持创建、查看和提醒，首页呈现今日事项及快捷入口。
- 提供常用清单模板。
- AI 助手支持文字和语音输入；云端语音识别或 AI 服务需明确告知用户。
- Android 端曾提出语音转文字和识图能力，具体范围与本地/云端边界待评审。

## 待 M1 评审的问题

- 单人模式的数据应存放于手机本地、NAS，还是两种模式可选？从单人模式转入家庭模式时是否需要迁移或合并数据？
- 家庭局域网连接如何发现 NAS 服务？NAS 地址变化时客户端如何恢复连接？
- 没有现成内网穿透时，互联网访问采用哪种安全连接方案？域名如何参与接入？需要评估部署难度、费用、账号安全和维护责任。
- NAS 不可用或客户端断网时，各模块允许查看、编辑或排队哪些内容？现有购物清单离线只读决策如何扩展到其他数据？
- 服务端部署方式、数据库、备份恢复、账号认证和数据加密应如何设计？
- AI、语音识别与图像识别哪些可在设备或 NAS 本地完成，哪些可使用云端服务，如何取得告知与同意？
- Android APK 的签名、升级、家庭成员安装与设备更换流程如何安排？

上述问题尚未作技术决策。此前讨论中的 Docker Compose、ASP.NET Core、PostgreSQL、Tailscale 等为历史候选建议，除非 M1/M2 再次评审通过，否则不视为已批准方案。
