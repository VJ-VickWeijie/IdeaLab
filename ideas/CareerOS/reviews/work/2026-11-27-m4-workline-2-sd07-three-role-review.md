1. **固定版本主证据 S1**：SAP《Simplification List for SAP S/4HANA 2021》，Document Version 1.25（2022-05-25），覆盖 Initial Shipment/FPS 1/FPS 2；§36.8，印刷页 789–790。该条目位于 system conversion 语境，涉及 VBUK/VBUP 状态表、相应单据表、VBFA 简化、VBTYP/VBTYPL 与 VBTYP_EXT、冗余索引表和客户追加字段转换说明。

## 有效闭环记录

每个闭环均记录一个具体质询、证据答辩、对文章的修订判断/实际内容变化，以及同一模拟角色对修订后的复核。未把来源没有覆盖的主张当作闭合事实。

### 普通读者视角（5 个闭环）

1. **质询**：文中说销售单据、交货、开票和财务凭证都属于“模型”，是否表示这些表直接连接？  
   **证据与答辩**：S1 只记载 SD 模型简化与对象表的状态变化；S2 只说明开票可过账到 Financial Accounting，没有字段级关系。业务对象词不等于表 JOIN。  
   **修订**：在第 1 节增加“业务导航词不是完整关系图”，并逐条说明相邻对象名称不能推出 JOIN。  
   **复核**：读者视角确认概念层与数据库层分开，修订通过。

2. **质询**：销售单据后面是否一定有一张交货和一张发票？  
   **证据与答辩**：S1 没有给出 SD 单据流基数；S2 只陈述开票能力，未定义必经步骤或基数。  
   **修订**：删除任何可能暗示固定 1:1 链的表达；练习改为列出业务对象和“待核关系”。  
   **复核**：读者视角确认正文没有把概念顺序说成必然单据链。

3. **质询**：开票单据过账到财务会计，是否就是财务凭证本身？  
   **证据与答辩**：S2 将“billing document”与“post to Financial Accounting”描述为处理能力，但没有说两者是同一对象或一对一记录。  
   **修订**：第 3 节改成“存在高层业务处理能力”，明确不由此推断凭证字段和引用基数。  
   **复核**：读者视角确认“可过账”没有被写成对象相同或固定基数，修订通过。

4. **质询**：开票单据状态是不是搬到了 VBRK 和一个开票项目表？  
   **证据与答辩**：S1 明确列出开票状态至 VBRK，而列明的 VBAP/LIPS 是项目表。该段未把开票项目状态列到 VBRP。  
   **修订**：第 2 节状态表注明只记录来源明确列出的 VBRK，不补写开票项目表。  
   **复核**：读者视角确认正文没有用熟悉的表名填补来源缺项。

5. **质询**：S3 提到 API，能不能据此直接按它开发销售数据查询？  
   **证据与答辩**：S3 是销售订单模拟 API 的 2021 增强记录，BD9 范围；不是通用销售/交货/开票 CRUD 目录，也未记录本文所需的完整字段关系。  
   **修订**：第 4 节写明它是模拟场景的窄示例，开发前须另外核对 2021 本地目录、合同和授权。  
   **复核**：读者视角确认 API 示例未被描述成完整数据模型或直接查询方案。

### 资深 SAP 配置顾问视角（5 个闭环）

1. **质询（严重范围缺陷）**：初稿把“VBUK/VBUP 状态表消除”写成脱离条件的日常系统操作结论。S1 的项目是否带有 system conversion 前提？  
   **证据与答辩**：S1 §36.8 明确写明处于转换到 SAP S/4HANA 的 Transition Worklist 语境；相应数据模型变化不能直接变成任意客户系统的逐表维护指令。  
   **修订**：第 2 节补上来源版本、文档日期、Initial Shipment/FPS 1/2、转换语境及“不是逐表操作说明”的限定；删除泛化语句。  
   **复核**：顾问视角按原问题复查，范围缺陷已修复；仍保留具体系统转换适用性待核。

2. **质询**：头状态/项目状态去向和读法是否严格按来源，不要把“类似”写成每种文档完全同构。  
   **证据与答辩**：S1 指名销售单据 VBAK/VBAP、交货单据 LIKP/LIPS、开票单据 VBRK；并仅以 VBAK 替换 VBAK+VBUK 举头状态读取例，项目“类似”。  
   **修订**：表格逐对象列出来源原有范围，并注明开票只列 VBRK；将一次 SELECT 的示例限制在来源所述头状态读取。  
   **复核**：顾问视角确认表述与列举对象相符，不外推开票项目状态。

3. **质询**：VBFA “简化”究竟证明了哪些字段、基数或算法？  
   **证据与答辩**：S1 只写“simplification of document flow table VBFA”，并未给具体主键、字段关系或路径。  
   **修订**：把 VBFA 结论限制为“存在简化事项”；增加未闭合项，不再提供任何替代字段或关系示例。  
   **复核**：顾问视角确认正文没有把来源标题扩写成模型事实。

4. **质询**：VBTYP 改成 VBTYPL 的具体边界是什么？  
   **证据与答辩**：S1 明确列出 VBTYP CHAR1 被 VBTYPL CHAR4 替代，并写 VBTYP_EXT 被消除；它没有给本文需要的所有接口兼容行为。  
   **修订**：第 2 节仅照录这两个字段级变化，未据此推导客户接口映射、历史值转换或通用替代方案。  
   **复核**：顾问视角确认字段类型与变化范围准确，外围行为仍留作待核。

5. **质询**：客户追加字段的兼容处理是否也被忽略，能否直接给 conversion 步骤？  
   **证据与答辩**：S1 另有状态 include 结构、自动转换及读取函数的特定扩展处理说明，属于转换场景，具体适用性依赖源系统客户字段。  
   **修订**：新增“转换与兼容性注意”，保留来源支持的条件和目标，明确本文不提供操作步骤或通用 API 名称。  
   **复核**：顾问视角确认兼容问题有披露，且没有把转换项目说明包装成客户实施指令。

### 普通 SAP 开发人员视角（5 个闭环）

1. **质询**：文章能否至少列出 VBAK、VBAP、LIKP、LIPS 的主键或示范 JOIN？  
   **证据与答辩**：S1 的 SD 简化条目提供状态迁移对象，不提供本文要写的完整主键、外键和一般 JOIN 条件。  
   **修订**：不加入未经证实的键表或 SELECT 示例；在第 3、5、7 节列出必须逐字段确认的事项。  
   **复核**：开发视角确认正文不会被误复制为生产 SQL。

2. **质询（严重过度泛化）**：来源说某视图可不加 JOIN，是否能总结为“SD 状态视图不需 JOIN”？  
   **证据与答辩**：S1 的直接例子限于单据头/状态字段整合后的视图和 VBAK 头状态读取；不是任意 SD 数据组合规则。  
   **修订**：第 2 节把该说明标成特定读取例子，并明确不是任意业务查询免 JOIN 规则。  
   **复核**：开发视角对照原问题复核，过度泛化已移除。

3. **质询**：What's New 页面是否已经证明 API released、权限和过滤合同？  
   **证据与答辩**：S3 记录 API 名称、模拟用途和新增属性/范围；本文没有固定版接口合同或本地权限证据。  
   **修订**：第 4、5 节分别区分“官方记录到 API 增强”和“实施前核对 released contract、认证、过滤、授权”。  
   **复核**：开发视角确认未把 API 目录消息说成系统调用测试或完整发布合同。

4. **质询**：可以用 VBFA 关联开票单号，再连接 FI 凭证行项目吗？  
   **证据与答辩**：S1 没有此关系映射；S2 没有字段级 FI 引用。由文档流名称和业务过账能力不能确定 JOIN 字段或基数。  
   **修订**：第 3 节把 VBFA、后续单据和 FI 凭证的逐字段引用列为未闭合事项，删除任何可执行连接暗示。  
   **复核**：开发视角确认不含未经证实的关系路径或字段。

5. **质询**：组织字段、ledger、company code 或权限是否可以从 FI-11 邻近文章补进 SD 模型？  
   **证据与答辩**：FI-11 当前文章只讨论其自身的财务模型边界，不证明 SD 到 FI 的键或权限。M3 的关联是研究依赖，不等于来源证明。  
   **修订**：第 3、7 节明确将组织键、FI 凭证引用和 API/CDS 授权列为待核；不链接或复用 FI-11 作为字段关系证据。  
   **复核**：开发视角确认没有跨篇推定，目标版直接证据仍待补。
