# SD-06｜销售配置查看

- 文章 ID：SD-06
- 状态：drafting
- 目标版本：SAP S/4HANA 2021 On-Premise
- 范围：识别销售业务行为背后的配置主题，按固定版本资料追踪到配置活动，并用受控的只读方式核对。
- 证据边界：本文只列有官方 SAP 资料直接支持的配置示例；不把某个 Scope Item、FPS 或具体文档中的 IMG 路径推广到所有销售场景。通用销售配置的完整 IMG 路径、系统内只读访问方式和授权对象尚未核实，因此保留 drafting。
- 系统验证：SAP 系统未连接；没有执行 IMG、事务码、权限或业务单据实机测试。

## 1. 为什么要看销售配置

销售订单中的业务行为可能受组织、单据控制、定价、交货、开票等多个配置对象影响。排查时先描述“发生了什么”，再确定对应业务对象和适用场景，最后查该版本官方文档里的具体配置活动。不能只凭一个字段或事务入口就判断根因。

本文把配置查看当作理解系统规则的过程，不提供修改生产系统的操作指引。配置界面能否打开、能否进入显示模式，以及用户能看到哪些节点，取决于当前系统版本、部署、角色和客户设置；本文没有证据给出通用授权角色、权限对象或只读事务码。

## 2. 先分清三类信息

| 类别 | 用来回答的问题 | 示例 |
| --- | --- | --- |
| 配置（Customizing） | 系统按哪些规则处理某类业务对象？ | 特定功能对应的条件类型或销售单据控制配置 |
| 主数据（Master Data） | 当前业务主体、产品或组织是什么？ | 客户、产品、销售范围 |
| 业务单据（Business Document） | 这一次业务实际输入和得到什么结果？ | 某张销售订单上的业务数据与处理状态 |

同一现象可能同时涉及以上类别。先用一个具体单据说明输入、结果和适用组织，避免把主数据缺失、单据输入错误或客户扩展误判为配置错误。

## 3. 有固定版本依据的配置示例

以下是范围受限的官方示例，可用于学习如何从功能描述追到配置活动。它们不是完整销售 IMG 导航，也不代表每个系统都启用了对应业务。

### 3.1 价格用途（Condition Purpose）

SAP Help 的 SAP S/4HANA 2021（版本选择器：2021.000）页面说明，可将 Condition Purpose 标识分配给 Condition Type，或分配给 Pricing Procedure 与 Condition Type 的组合；该标识可供应用代码作为业务用途参考。页面给出的配置活动为：

Sales and Distribution → Basic Functions → Pricing → Condition Purposes in Pricing

这个路径支持的是该项价格用途配置活动。它不能证明销售定价过程中所有条件、访问顺序、定价程序确定因素或科目决定路径。

### 3.2 销售单据类型中的开票阻止（特定审批场景）

SAP S/4HANA 2021（2021.000）的 Debit Memo Request Approval Workflow 文档说明，在该审批工作流场景中，相关借项凭证申请类型若设置了 Billing Block，须按文档所述在配置中移除。文档给出的活动为：

Sales and Distribution → Sales → Sales Documents → Sales Document Header → Define Sales Document Types

该例仅用于 2021 版借项凭证申请审批工作流所述前提。不能据此概括所有单据类型、所有开票阻止用途或客户审批设计。

### 3.3 订阅订单的固定价格（2021 FPS01 专项示例）

SAP S/4HANA 2021 FPS01 的 What's New 文档为订阅订单固定价格给出条件类型 PSFX，并列出条件类型维护以及相关定价程序维护活动。文档标明其适用于订阅订单的特定功能范围，并展示该定价程序的对应增强。

因此，这只能作为 2021 FPS01 订阅业务的版本专属例子；不能当作初始版 2021 通用销售定价规则，也不能推广到普通订单或其他行业方案。

## 4. 可复用的只读核对步骤

1. **描述现象**：记录单据类型、业务结果、发生环节和可确认的输入；不复制客户数据或敏感单据。
2. **圈定场景**：确认产品版本与 FPS、部署方式、业务范围、国家/本地化和使用的应用。缺一项时把结论写成待核。
3. **区分对象**：说明怀疑的是配置、主数据还是单据本身；若可能有多个原因，分别列出。
4. **找固定版文档**：使用 SAP Help 的固定版选择器或对应 SAP 2021 FPS 文档，记录页面标题、文档版本、章节、适用功能和前提。动态 latest 可用于发现线索，不能作为固定版 2021 证据。
5. **追踪配置活动**：仅在官方文档直接列出时记录完整路径，并保留产品范围、版本和场景限制。没有逐项来源的 IMG 层级不补猜。
6. **申请只读核对**：由系统管理员或授权负责人确认本系统可用的显示访问方式和所需权限。不要由事务码可启动、角色名称或菜单可见性推断用户有权看配置。
7. **留痕并复核**：记录依据、未覆盖条件、观察到的界面范围和日期。若未连接目标系统，只记录“文档核对”，不写成系统核验。

SAP 文档中的配置路径只说明文档所述功能活动的位置，不等于当前客户系统实际菜单路径、已启用状态或用户授权结果。

## 5. 目前不作的推断

- 不提供通用 IMG 树、事务码清单、显示/修改事务区分或具体授权对象；这些需要 S/4HANA 2021 对应组件资料和目标系统权限证据。
- 不推断任一销售配置会自动产生特定 FI 分录、收入确认、税额或银行收款结果。
- 不把定价配置示例等同于条件记录主数据，也不从某条配置路径推断定价结果。
- 不列数据库表、字段、配置视图、配置传输对象或 API；本次所读来源没有为本文目标提供充分数据模型证据。
- 不把 FSD 动态 latest 页面当作固定版 2021 证据。M3 的来源复核曾记录该动态页面的不同版本快照；本次检索到的 PDF 头部也显示了不同文档版本，故只将其作为功能范围查找线索，不据此确定某一 FPS 的行为。

## 6. 练习：用公开文档做配置追踪

选一个上文列出的官方示例，不登录业务系统，填写以下问题：

- 该配置活动对应哪个产品版本、FPS 和业务功能？
- SAP 文档直接说明了什么输入或系统行为？
- 适用前提是什么，哪些场景没有被覆盖？
- 该路径是官方文档路径，还是目标客户系统中实测的可见路径？
- 是否有证据确认目标系统和练习者的只读访问权限？

如果最后两项没有证据，答案写“未验证”，不要尝试保存配置或在生产系统中试操作。
