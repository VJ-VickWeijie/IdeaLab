## 1. 业务对象与技术模型要分开

学习销售业务时，会遇到销售单据、交货单据、开票单据以及后续财务会计处理等对象。它们可以帮助我们按业务问题组织知识，但不能仅凭这些名称画出完整的数据库关系图。

本文把“销售单据、交货单据、开票单据、财务会计凭证”当作业务导航词。它们之间是否存在引用、引用在哪个层级、是否一对多或多对一、适用哪些单据类别和流程，都需要各自的目标版证据。本文不把概念上的业务顺序当成表关系或固定单据流。

**概念与技术对象的边界：**

- “单据头/项目”是业务和教学层级；它不自动给出数据库表主键、字段清单或项目级关系。
- 一项状态信息与单据头或项目表的整合，不表示其他业务数据也都在同一张表。
- 两个表名同时出现，不足以推出可用的 JOIN 条件。
- 某个 API 对一个场景可用，不表示它是完整的销售、交货和开票数据接口目录。

## 2. SAP S/4HANA 2021 固定版资料明确写出的变化

SAP《Simplification List for SAP S/4HANA 2021》版本 1.25（2022-05-25），覆盖 2021 Initial Shipment、Feature Pack Stack 1 和 2。§36.8 的 SD 数据模型条目位于系统转换语境。其内容可作为理解该清单所列目标数据模型变化的直接来源；它不证明任一客户系统当前已处于此模型，也不是客户逐表迁移或操作指引。[S1]

| 主题 | 该资料明确写出的内容 | 本文可以得出的有限结论 |
| --- | --- | --- |
| 状态数据 | 资料说明，VBUK、VBUP 状态表被消除；状态字段移到对应单据头/项目表：销售单据 VBAK/VBAP，交货单据 LIKP/LIPS，开票单据 VBRK。 | 可以按该条目理解状态数据简化方向。对开票单据，本文只记录来源明确列出的 VBRK；不补写未在该段列出的开票项目表。 |
| 读取状态 | 来源举例：销售单据头数据与头状态可通过一次 SELECT（VBAK）读取，而不是分别查 VBAK 和 VBUK；项目数据类似。 | 这是来源给出的特定状态读取示例，不构成任意业务查询都可免 JOIN 的规则。 |

### 转换与兼容性注意

同一条目也说明了 VBUK/VBUP 客户追加字段的转换处理：相关字段需位于指定的状态 include 结构中，才会被相应自动转换和可替代直接读取已弃用状态表的读取函数考虑。该说明属于系统转换及自定义扩展的特定处理；本文不提供转换操作步骤，也不把读取函数当作已核实的通用 API。升级项目应按源系统实际扩展、目标版 SAP 转换文档及适用 SAP Note 逐项确认。[S1]

## 3. 单据流、关联基数和会计凭证：目前能说到哪里

固定版 Simplification List §36.8 仅说明 VBFA 数据流表发生简化，没有在该条目列出完整字段、键或关联基数。相邻 §36.9“VBFA - Indirect Docflow Relationships”补充的是早期版本历史：它分别讨论两类特定情形——从 SAP ERP 转换到 1511 SP00–SP03 或 1610 SP00–SP01；以及新安装系统的起始版本为或曾为 1511 SP00–SP03 或 1610 SP00–SP01。该条目记录早期版本曾移除 VBFA 字段 STUFE，初始发行版只存直接关系、间接关系未存储且在转换中被删除；并说明间接关系在 1709 SP00、1610 SP02、1511 SP04 等版本重新存储。它还明确列出需要重建缺失文档流的历史路径：系统转换到 1610 SP00/SP01 或 1511 SP00–SP03；以及新安装在 1610 SP00/SP01/SP02 或 1511 SP00–SP04。其余特定升级路径应按 SAP Note 2418242 核对。该条目提醒直接读取 VBFA 的自定义代码须检查，因为 VBFA 及其内容发生不兼容变化。

这些是固定清单对旧版本安装/转换历史的说明，不表示 SAP S/4HANA 2021 的新装或一般系统普遍缺少间接关系，也不要求 2021 客户执行重建。该条目没有给出 SAP S/4HANA 2021 的完整字段/键/基数合同，也不能判定某个客户系统实际经历了哪条历史路径。

因此，当前固定版资料仍未给出销售单据项目到交货项目、交货到开票或开票到财务凭证的完整关系映射。本文不提供主键表、外键表、JOIN 示例或“一个来源单据必然生成一个后续单据”的规则。

SAP S/4HANA 2021 Feature Scope Description 的动态官方 PDF 快照，文档版本 11.0，日期 2026-07-22，标识为 SPS10。其 §2.10.2.8 概括说明可创建和管理开票单据、将其过账到 Financial Accounting。这个来源支持“存在开票到财务会计的业务处理能力”这一高层描述；它没有据此给出财务凭证字段、主键、引用基数或收入、税和收款规则。该 PDF URL 含 latest，本文将它明确作为**实际读取的 SPS10 快照**，不冒充固定版 2021.000 页面或初版资料。[S2]

核对任一具体关系时，至少还需要固定到目标版本和场景的官方字段定义、单据流/接口合同、发布状态及授权资料。当前仍未闭合的项目包括：

- VBFA 及后续单据关系的字段、主键、外键和基数。
- 销售组织、分销渠道、产品组、工厂、库存地点等组织字段在特定对象中的键与约束。
- 销售、交货、开票对象与会计凭证之间的字段级引用和多对多/拆分场景。
- 兼容视图、旧程序迁移及客户扩展在指定 2021 FPS 中的适用行为。

## 4. API 示例只能说明一个窄范围

SAP Help 固定版官方页面的检索索引摘录（URL 锁定 version=2021.000；本轮直接打开页面为 0 行，未直接复读正文）显示：OData API **API_SALES_ORDER_SIMULATION_SRV** 在 SAP S/4HANA 2021（2021 年 10 月）记录了若干销售订单模拟的头级和项目级属性增强，范围标为 BD9 Sell from Stock。[S3]

这个例子可以说明：固定版文档记录了一个销售订单模拟 API 的具体增强。它**不能**证明：

- 该服务是销售、交货、开票全部对象的通用 CRUD 接口。
- API 字段与数据库表字段逐一对应。
- 本地系统的具体版本、发布合同、权限、过滤、分页和错误行为已验证。
- 该 API 可替代未经核对的直接表查询。

要把 API 用于开发，仍需在目标系统的 2021 On-Premise API 目录和接口文档中确认服务版本、发布状态、认证/授权及业务范围。本文未连接 SAP，也未调用 API。

## 5. 建议的学习和开发核对步骤

拿到一条“SD 表关系/API”说法时，可依次核对：

1. **锁定对象和场景**：销售单据、交货、开票、财务凭证，及具体处理流程。
2. **锁定来源版本**：确认它是 SAP S/4HANA 2021 On-Premise 的固定版本资料，还是标明 SPS/FPS 的实际快照。
3. **逐字段找证据**：分别确认对象类型、字段、键、基数和版本范围。表名相邻或业务上相关，不足以作证。
4. **区分兼容与发布接口**：旧表兼容、转换工具、读取函数和 released API 是不同概念；不能互相替代。
5. **记录授权边界**：目标系统是否开放该 API、CDS view 或读取权限，需看接口目录和本地角色。本文没有验证权限。
6. **没有直接依据就停在未知**：保留待核问题，不编写生产 JOIN、主键或接口映射。

- **不能先填入的内容**：表主键、项目关联字段、VBFA 查询条件、单据数量基数、FI 凭证引用字段。
- **下一步证据**：按目标 FPS 检索对应对象的 SAP Dictionary/官方 API 规范、特定业务流程及授权资料；若系统未连接，就把这几项保留为待验证。
