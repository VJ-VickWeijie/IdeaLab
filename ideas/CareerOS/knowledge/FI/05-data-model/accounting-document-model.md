# FI-11｜财务凭证与总账数据模型

> **状态：drafting（核心范围仍待证据）**  
> 目标版本：SAP S/4HANA 2021 On-Premise。本文只写当前固定版资料直接支持的模型背景；尚未把 BKPF/ACDOCA/BSEG 的完整字段、主键、基数、API 发布状态或权限写成结论。SAP 系统未连接，未做实机验证。

## 学完后应该能做什么

- 说明财务凭证与报表数据模型为什么要分业务层和技术层理解。
- 解释 Universal Journal 在 FI 与 CO 报告视角上的高层意义。
- 区分概念上的“凭证头/行项目”和数据库表、字段、连接关系。
- 判断一条数据模型或 API 说法是否有 S/4HANA 2021 直接证据。

## 1. 为什么学习这张模型图

企业需要记录财务业务，并在账簿、管理分析和报告中按适用口径查看。SAP 的 S/4HANA 2021《Simplification List》将 Universal Journal 描述为财务报告的数据存储背景：内外部报告可从同一报告数据源读取，并以 account 作为统一因素。该段属于 2021 初始发行、FPS 1/2 文件中的转换说明；不能据此推断所有业务流程都写入同一物理表，或所有字段都相同。

这不表示 FI 与 CO 的业务工作变成同一流程。该资料仍分别列出总账凭证、固定资产活动、Controlling 中的分摊与结算等业务活动；统一的是报告数据背景，不是每项业务操作。  
**证据范围：** SAP《Simplification List for SAP S/4HANA 2021》，§8.1，印刷页 200–201；见来源 S1。

## 2. 先分清业务概念和技术对象

可以先用下面的概念图学习，不把箭头当成数据库 JOIN：

`业务事件 → 财务凭证 → 账簿 / 管理分析 / 报告`

- **业务事件**：例如企业确认一项收入、费用或资产变化。具体业务与过账条件由相应流程文章解释；本文不推导采购、税务或自动科目分录。
- **财务凭证**：用来记录业务会计结果。学习时可将它想成“共享说明信息 + 一条或多条记账明细”；这是概念帮助，不是已验证的 SAP 表结构。
- **总账与管理分析**：两者提出的问题可能不同。财务会计关注正式账簿和对外报告；管理会计关注内部责任、成本或经营分析。用途可以共享报告数据背景，但不能推出每个凭证都带有某个 CO 对象，也不能推出 FI 与 CO 自动产生两笔费用。
- **报告**：报告只呈现其数据源、筛选条件与权限范围支持的内容。字段、汇总口径和时点需逐个报告核实。

**关键边界：** “凭证头/行项目”是业务和教学语言。不能只凭这一概念就认定 BKPF、ACDOCA、BSEG 的字段、键、行数比例或 JOIN 条件。当前读取的固定版资料不足以完成这些断言。

## 3. Universal Journal：能说什么、不能说什么

固定版 2021 资料支持的高层说明是：Universal Journal 改变了财务报告相关交易数据的存储和读取背景，帮助协调内外部报告需求；特定转换说明提到旧总额记录及索引表的变化，并通过 compatibility view 保留某些旧读取路径。

该段有明确的转换语境，不能简化为以下说法：

- “S/4HANA 的全部财务数据只在一张物理表里。”
- “每个 FI/CO 对象都能用同一组字段解释。”
- “同名 compatibility view 等于原始物理表。”
- “旧 ABAP 的 SELECT 方式永远受支持。”
- “compatibility view 可以安全写入。”

S/4HANA 2021 What's New 还描述了一个**特定** deferred summarization 场景：该功能下，journal entry 明细会移到 ACDOCD，汇总后的明细保留在 ACDOCA。此例只说明该功能的特定处理，不能外推为 ACDOCA 的通用粒度或完整键定义。  
**证据范围：** SAP《What's New in SAP S/4HANA 2021》，§3.6.1.26；见来源 S2。

## 4. BKPF、ACDOCA 与兼容视图：暂定导航

以下对象只是待逐字段核实的候选，不是现阶段可直接开发的接口。

| 对象/概念 | 当前可写的结论 | 仍缺的目标版证据 |
| --- | --- | --- |
| Universal Journal | 固定版转换资料说明其报告用途和数据模型变化背景。 | 通用业务覆盖范围、来源应用的写入条件和字段来源。 |
| ACDOCA | 2021 What's New 在一个特定成本汇总场景中明确提到该表与 ACDOCD。 | 一般行粒度、主键、完整字段及与账簿/业务对象的基数。 |

| Compatibility view | 2021 转换资料说明特定历史对象的读取兼容方式及写入边界。 | 指定系统与表的 DDIC 定义、实际重定向、FPS 差异和访问合同。 |
| SAP 发布接口 | 开发前须核对目标版接口目录与发布状态。 | S/4HANA 2021 On-Premise 对应 API/CDS 的版本、release contract、字段、过滤和权限。 |

“SAP 发布接口”这一行是本篇的开发准入原则，不是对某个具体 CDS/API 在 2021 已发布的断言。较新的 SAP Help 页面可能展示以 ACDOCA 为来源的 CDS view 或授权前提；未锁定至 2021 On-Premise 的页面，不作为目标版结论依据。

## 5. 用业务问题读数据模型

字段级证据未确认前，先画业务概念，不写表连接：

1. 选一个已学过的虚构业务事件，标明它属于 FI、CO，或两者协作的场景。
2. 写下想回答的问题，例如“这个期间有哪些财务结果需要复核？”不预设具体事务码、字段或筛选条件。
3. 区分业务凭证、会计结果和管理分析各自回答的问题。
4. 列出仍需从 2021 官方资料确认的对象、字段、键、权限和接口。
5. 目标版来源确认后，再把概念图转为 CDS/API 或数据表关系图。

练习不需要连接或修改企业 SAP 系统，也不把虚构关系当成真实查询。
