# QM-04｜检验结果与使用决策

- 文章 ID：QM-04
- 状态：drafting（目标版证据受限）
- 目标版本：SAP S/4HANA 2021 On-Premise；ECC 仅作必要差异对比
- 本篇可确认范围：固定版 2021 SAP Help 支持在检验批工作清单记录结果和作使用决策；在所述 planned samples 场景，UD 有明确前提；库存相关检验批可在有未过账数量时于 UD 前、期间或之后处理库存过账；某类代码的后台处理指标可决定过账建议是否自动处理。
- 状态原因：固定版来源没有闭合一般结果录入步骤、结果字段/缺陷评估、完整自动 UD 规则、撤销、权限角色映射、库存与财务影响。本篇不等于完整检验操作指南。
- 系统验证：SAP 系统未连接；未查看客户应用、配置、检验批、结果、权限、物料凭证或会计凭证，未做实机测试。

## 1. 先把四个动作分开

| 动作 | 对学习者意味着什么 | 本篇可确认的边界 |
| --- | --- | --- |
| 记录检验结果（results recording） | 把检验观察记录到检验批所关联的检验过程中。 | 2021 固定版 Manage Inspection Lots 应用资料确认工作清单支持记录结果；UD 页面要求先记录所有必需检验特性的结果。它没有给出通用录入画面、字段或评估算法。 |
| 评价样本与关闭特性 | 判断样本/特性是否已完成处理。 | 仅在固定版 UD 页面所述 planned samples 情境下，该步骤列为作 UD 的前提；不能扩展成所有检验变体的状态机。 |
| 使用决策（usage decision, UD） | 确认检验批的检验已完成，并说明该批货物是否接受或拒绝使用。 | 固定版页面列出了手工单批、工作清单多批和周期作业自动处理的方式；这些方式及前提按原页面语境理解。 |
| 库存过账（stock posting） | 对库存相关检验批的数量选择后续库存处理。 | 固定版页面允许在尚有可过账数量时于 UD 前、期间或之后过账。UD 与库存过账不是同一个动作，也不能假设 UD 自动把所有数量转成非限制使用库存。 |

SAP S/4HANA 2021 固定版 Manage Inspection Lots 页面把“记录结果”和“作使用决策”列为工作清单可执行的不同操作。固定版 Usage Decision 页面则说明 UD 表示检验完成及接受/拒绝使用。把二者分开有助于阅读 SAP 流程，但并不意味着本文已经证明所有业务场景的完整状态转换。

## 2. 什么时候可以作使用决策

SAP S/4HANA 2021 固定版 Usage Decision for Inspection Lot 页面在其 planned samples 说明中列出以下前提：

1. 当前用户具有适当授权。
2. 检验批已释放。
3. 所有必需检验特性的结果已记录。
4. 所有特性已关闭，并在结果记录处理中评价了全部样本。
5. 当前没有阻止使用决策的状态。

满足页面所述条件后，UD 表明该批货物被接受或拒绝使用。页面列出三种处理方式：对单个检验批手工处理、通过工作清单手工处理多个检验批，或由预先安排且周期运行的作业自动处理。

这些是该 2021 页面所述情境的前提和方式。它没有在本轮核验中给出完整自动 UD 资格规则、作业配置、每种检验来源的差异或客户角色名称。页面只要求“适当授权”，并未据此证明具体用户、事务码、Fiori 角色或权限对象。未满足前提时会发生什么，也应按目标版直接资料和实际设置逐项确认。

## 3. UD 和库存过账分别核对

固定版 Stock Postings 页面区分检验批是否与库存相关，并说明：

- 非库存相关检验批不能通过该 QM 库存过账功能处理库存。
- 对有未过账数量的库存相关检验批，库存过账可以在 UD 之前、UD 期间或 UD 之后进行。
- 页面列出非限制使用库存、报废、样本使用、冻结库存、新物料、样本储备和退货等目标类别；选择是否适用要保留原场景与页面前提。
- 过账会生成物料凭证（material document）。该信息不证明每种过账都产生 FI 凭证、发生价值变化或使用相同会计科目。
- 对检验目录类型 3 的 UD 代码，选定集可以提供库存过账建议；该代码设有后台处理指标时可自动处理建议，否则按页面描述需要人工确认。

由此可以得出两个有限结论：第一，检验批作了 UD 不等于所有开放数量已经完成库存过账；第二，存在自动 UD 处理方式也不能证明库存过账自动发生。代码、选定集和后台处理条件只适用于上述页面明确说明的情境，不能作为所有检验批的通用设置。

## 4. 用一个离线案例练习区分动作

假设采购收货后建立了检验批，检验人员记录了结果，部分数量仍有待处理。不要先假设“结果合格，所以库存已放行”，而是逐项标注：

| 要问的问题 | 可依据本文回答的部分 | 仍需核实的部分 |
| --- | --- | --- |
| 结果是否已经记录？ | UD 页面要求所有必需特性的结果先完成；工作清单支持结果记录这一动作。 | 具体特性、字段、结果值、缺陷处理与评估算法。 |
| 现在是否满足 UD 前提？ | 检查批是否已释放、必需结果/特性/样本是否处理完成、是否有阻止状态，以及授权前提。 | 客户批次状态、具体状态控制和当前用户授权。 |
| UD 表示什么？ | 在页面语境内表示检验完成，并确认接受或拒绝使用。 | 客户后续业务动作、自动跟进行为及每种 UD 代码的结果。 |
| 开放数量如何处理？ | 库存相关批次可在 UD 前、期间或之后过账；页面列有若干候选目的地。 | 当前库存类型、适用目标、数量、过账原因、具体移动和价值影响。 |
| 系统是否自动处理？ | 自动 UD 作业与特定 UD 代码的自动库存过账是两个不同机制。 | 该客户是否配置相应代码/选定集/后台处理，以及作业是否具备资格。 |

这是资料阅读练习，不是系统操作步骤。SAP 系统未连接，表格中的“检查项”未在客户系统实测。

## 5. 本篇明确不下的结论

以下内容尚无足够固定版直接证据，不在正文中编成确定规则：

- 一般结果录入的完整屏幕步骤、各类定量/定性检验特性字段、缺陷记录与自动评价算法。
- 自动 UD 的完整适用条件、作业参数、按检验来源/工厂/检验类型的差异和失败处理。
- 已作 UD 的撤销、重做、纠正或后续库存凭证冲销规则。
- 每种库存目标、移动类型、数量变化、估价及 FI/CO 凭证影响。
- “接受使用”在所有业务配置中必然等于转到非限制使用库存，或“拒绝使用”必然等于报废/退货。
- 具体事务码、Fiori 页面在客户系统中的可用性、角色映射、权限对象和只读/修改边界。
- EWM 中的检验批、部分使用决策或仓库任务处理；EWM 资料不能替代或泛化为普通 IM 规则。
