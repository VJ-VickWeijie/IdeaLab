# MM-04｜采购申请与订单机制

> 状态：drafting｜M4 批次 A｜目标产品版本 SAP S/4HANA 2021 On-Premise。本文的流程主张依据 SAP S/4HANA 2021 Feature Scope Description 文档版本 11.0（2021 SPS10，2026-07-22）所列高层功能；该官方 PDF 使用动态 `latest` 链接，Work 于 2026-11-26 读取。它不提供所有客户的 PR→PO 转换规则、工作流条件、事务权限或实机结果。

## 先理解两张单据为什么分开

采购申请（Purchase Requisition，PR）表达企业内部“需要采购什么、数量是多少、希望何时到货或提供服务”的需求。业务部门可以提出采购需求；SAP FSD 对系统中的手工 PR 创建者描述为采购人员或其他专员，MRP 需求也可能生成 PR。业务需求提出者不等同于有权在系统中直接创建 PR 的用户；本文不枚举所有其他创建来源。

采购订单（Purchase Order，PO）是向外部供应商提出的采购请求或指令，明确材料数量及交付时间，或服务的履行期间。它把内部需求推进为对外采购单据。能否创建、是否需要审批、参考哪些采购信息以及怎样发送给供应商，受业务场景和系统配置影响。

| 学习问题 | PR：采购申请 | PO：采购订单 |
| --- | --- | --- |
| 主要表达什么 | 企业内部的材料/服务需求 | 发给外部供应商的采购指令 |
| 需求如何出现 | 人工提出，或由 MRP 等需求驱动 | 根据 PR 创建，也可参考既有 PO、采购信息记录或合同，或从头创建 |
| 单据面向谁/表达什么 | 面向企业内部的采购需求 | 是面向外部供应商的采购请求/指令；本文不据此判断具体审批/发送状态或合同法律效力；引用合同可能发起合同调用 |
| 审批方式 | 可能使用 release strategy 或 flexible workflow；“自动审批”针对 PR 内部需求 | flexible workflow 可配置自动、单步或多步处理；“自动放行”针对 PO 采购订单 |
| 本文不据此推断 | PR 批准后必然生成一张 PO | 每一张 PR 与 PO 一定一对一、某一事务码在你的系统可用 |

初学者可先按“处理哪张单据”区分这两个词：PR 的自动审批处理内部采购需求，PO 的自动放行处理采购订单。SAP FSD 将其分别列在两种单据的 workflow 描述中；本文不把它们说成同一种审批状态，也不据此推断 PR 会自动生成 PO。

PR 与 PO 不能合并成“同一张单据的前后状态”来理解。组织需要 PR 来收集/澄清内部需求，需要 PO 来形成针对供应商的采购指令；两个阶段可以有不同的来源、审批与处理条件。

## 一条供学习的业务路径

下面用“业务阶段”解释常见问题。步骤编号只是阅读组织，不表示每个系统都执行相同步骤，也不代表货源确认、审批、PO 创建有固定先后关系；具体顺序和单据变体须按场景核实。

1. **提出需求。** 业务部门可以提出采购需求；目标版 FSD 对系统中的手工创建描述为采购人员或其他专员，MRP 等计划结果也可能形成 PR。谁能在具体系统录入取决于角色和授权，本文不把业务需求方说成必然的系统创建者。
2. **补充采购决策信息。** 根据场景，PR 项目可分配建议来源中的来源，也可由采购人员指定供应商；材料/服务项目还可涉及账户分配。来源选择的对象和算法见 [MM-03](info-record-sourcing.md)，不能仅凭存在信息记录或货源清单推断最终来源。
3. **按适用规则处理审批。** SAP S/4HANA 2021 的功能范围列出 PR release strategy 或 flexible workflow。FSD 描述 PR flexible workflow 可为自动、单步或多步审批；配置专家可以设定审批人/审核人，并可采用角色或用户分配等方式。具体是否触发、哪些项目/金额适用、谁是审批人、无审批人时如何处理，均须看实际 workflow/release 配置。这里列出的自动/单步/多步、审批人分配和退回修改均指 flexible workflow 的高层能力，不用于概括 release strategy 的规则。
4. **选择后续采购单据。** PR 项目可以进入后续采购处理。FSD 列出多个 PR 汇总到一个 PO 的能力，但没有给出哪些 PR 可合并的完整资格条件；已分配来源时，也可以规划后台自动从 PR 创建 PO。来源分配是 FSD 提到的条件之一，但不能据此断言来源已分配就足以触发作业或必然生成 PO。
5. **确定 PO 的参考与内容。** PR 可作为 PO 的来源；PO 也可参考既有 PO、采购信息记录或合同，或从头创建。FSD 在此列的是创建 PO 时可用的参考来源；本文不据此主张持久数据关系、精确字段复制或表/API映射。引用合同会发起合同调用，可先理解为基于现有合同创建具体采购订单的业务动作；合同本身不等于该 PO。本文不展开合同条款、剩余数量或履约规则。
6. **处理 PO 审批与输出。** 2021 FSD 描述 PO flexible workflow 支持自动、单步或多步审批；是否必须审批或会自动放行取决于 workflow 设置。SAP 文档也提到采购订单输出可以打印或邮件发送。本文只说明可能涉及的处理环节，不规定它们的固定先后；具体审批条件、状态和发送渠道依客户配置与权限而定。
7. **进入后续执行。** PO 后续可能有供应商确认、收货和发票等处理。它们各自有物流与财务影响；本篇不把 PO 创建/审批等同于收货、发票验证或付款。后续分别参见 MM-05、MM-06 与 [PROCESS-01 采购到付款](../../../business-processes/P2P/purchase-to-pay.md)。

## PR 与 PO 之间不是固定的一对一映射

离线学习时可以用一个简化例子：

> 计划员为广州工厂的一种包装材料提出 100 件需求；采购人员核对来源并完成适用的需求审批，之后按采购场景生成采购后续单据。

这个例子只表达内部需求如何进入后续采购处理，不预设供应商、价格、审批金额线、来源优先级或会计分录。不要由示例推导以下规则：

- 一条 PR 必须生成一条 PO，或一条 PR 一定只进入一张 PO；
- 多条 PR 是否能合并，或合并后字段/价格/来源如何处理；
- PR 何时自动转成 PO、何种条件下需要采购人员手工创建；
- PR 审批、PO 审批与合同审批的先后或继承关系；
- 任何具体文档类型、字段、编码、状态、事务码或客户权限的固定组合。

SAP S/4HANA 2021 FSD 明确列举了“根据 PR 创建 PO”“多个 PR 汇总到一个 PO”“创建合同”和“已分配货源时计划后台自动创建 PO”等功能方向。这些是可用流程选择，不是一个适用于所有客户的自动转换算法。

## 审批、配置与业务责任：看什么、不猜什么

审批的业务作用是让授权角色在采购单据继续处理前检查需求、责任和必要条件。对于学习者，先分清三件事：

- **PR 审批**：决定内部需求是否能继续进入采购处理。FSD 描述了 release strategy 与 flexible workflow 两种相关机制；自动/单步/多步审批、审批人分配和退回修改等具体描述属于 flexible workflow，不据此推导 release strategy 的配置或状态规则。
- **PO 审批**：在对外采购指令层面控制是否审批或自动放行。可把“自动审批”理解为 PR 流程处理内部需求，把“自动放行”理解为 PO 流程处理采购订单；这是两个单据上的不同工作流关口。FSD 分别描述这两种能力，本文不把它们等同为同一机制或状态，也不推断自动处理的具体状态变化。是否必须审批或自动放行取决于 PO workflow 设置；某些关键修改是否重新触发审批也由系统设置决定。
- **创建后续单据**：审批结论、来源分配和 PO/合同/RFQ 的创建是相关但不同的业务决定。不能把“已批准 PR”简化为“系统必然自动生成 PO”。

SAP 2021 的功能资料支持 flexible workflow 的存在及高层能力，但本篇不提供金额阈值、采购组织/公司代码审批矩阵、代理人确定逻辑、角色配置、重启字段、release code、具体 IMG 路径或配置传输流程。实际配置还受启用的产品范围、组织、单据类型、授权及企业规则影响；在没有固定版直接资料或客户系统核验时，这些均不写成通用事实。

## 只读练习

不需要登录 SAP 或修改生产系统。请对以下三个采购需求分别写出“当前是内部需求还是供应商指令、还需要哪些审批/来源信息、下一步有哪些已被目标版来源支持的选择、哪些细节仍需核实”：

1. MRP 为常规材料生成一项采购需求。
2. 使用部门为一项服务提出需求，但服务细节尚未完全确定。
3. 采购人员要把若干已批准需求集中安排给供应商，并评估是否从合同中调用。


### 参考思路

- **MRP 需求**：先识别为内部 PR；FSD 支持 MRP 需求可产生 PR。还要核实适用的来源与审批设置。可以基于 PR 创建 PO，但不能只凭“MRP 已产生 PR”推断自动生成 PO。
- **未完全明确的服务需求**：仍是内部 PR；目标版来源提到未计划服务/材料可用限额项表达。审批以及后续 PO 的具体限额、服务记录和财务处理仍须查对应资料。
- **多项已批准需求与合同**：FSD 支持将多个 PR 汇总到一个 PO；引用现有合同可能发起合同调用。它不保证题设必须合并成一张 PO，也不提供合并条件或合同调用的全部规则。

以上只是按已列来源自检的方向，不是标准答案中的固定系统步骤。
合格答案不需要写出某个固定事务码，也不能擅自假定每条 PR 的转换比例、审批阈值或会计结果。应能区分 PR、PO、合同和 RFQ 的业务角色；若题目要求具体的系统状态/配置结果，应指出需要目标版本资料或真实系统权限核实。
