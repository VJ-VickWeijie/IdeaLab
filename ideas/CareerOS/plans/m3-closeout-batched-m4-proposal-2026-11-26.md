## 1. 决策背景

现有 M3 控制矩阵已将批准清单的 99 个文章 ID 与路径逐项登记，无缺失／额外／重复；每项含来源记录、状态、Work 下一步和已知复核范围。矩阵也明确声明它不是事实全面核验、文章通过或 M3 放行；目标版本与场景、主张级证据边界、实际阅读者／日期、独立复核范围／日期／基线和逐项 M3 判定仍有未归一项。

固定版 AI-Workflow V1.1（939ec44036d89cd91622ab96b938be9f02479026）将 M3 定义为实施规划成果与执行授权决策。独立普通读者、资深 SAP 配置顾问、普通 SAP 开发人员评估一致建议：维持准确性和逐篇审核标准，但不将 99 篇的全部事实闭合、历史复核元数据收敛和全库审查容量预先落实设为任何正文开始前的统一条件。

## 2. 建议的 M3 收尾条件

接受以下项目级计划成果后，把 M3 送交独立门禁复核和所有者审批；在批准前不改变当前状态。

1. 99 个正式文章 ID 与路径继续以批准 manifest 为准；不缩减 99 篇，也不把 11 个纯结构导航分类算作文章。
2. 为每项使用统一状态：**可写**（拟写的核心事实有相称直接依据）、**限缩可写**（只写已证实范围，删除或明确列出缺口）、**暂缓核心**（文章学习目标依赖尚无充分依据的关键事实）。需要目标 SAP 系统、客户配置、权限、性能或实际执行结果的信息，另列**目标环境待验证**；不得把它标成已有知识库事实。
3. 每项至少记录：文章 ID／路径、目标产品版本及场景、拟写核心主张、具体来源与其支持范围、未支持边界、文章级状态、依赖、Work 负责人和下一动作。对历史阅读者、日期、独立复核者／日期／提交基线无法还原的字段明确记“未知／待补”，不推断、不伪造。
4. 五项重点阻碍保留为开放风险，改为相应文章及主张的准入限制；其余不相关、有独立证据支持的文章可以进入批次审查。矩阵中的来源状态不自动代替上述主张级准备。
5. 明确批次排序、依赖门槛、批次容量核实方法、真实审核记录格式、严重缺陷回退与 HANDOFF 更新责任。容量只需在各批启动前落实，不预设 99 篇的长期额度或吞吐。
6. M3 计划自身经独立评估后向所有者提交；只有明确批准“修改项目级 M3 出口”的决定，才能按新条件收尾 M3。AI-Workflow 的通用门禁文件保持原样。

## 3. 分批 M4 建设提案

### 第一批

M4 获批后，Work 从控制矩阵与依赖图中选取 **3～5 篇**证据边界清楚、依赖少、且不依赖五项未闭合核心断言的正式文章。选篇 ID 与选择理由必须在该批开工记录中明确；本提案不预先冒称某篇已经就绪。

首批用于验证真实的写作、引用、版本限定、审核记录和容量节奏。它不是缩减交付目标或只交样板；后续批次继续覆盖完整 99 篇及对应流程、课程与审核材料。

### 后续批次

按知识依赖与证据成熟度组批：基础概念／主数据，模块业务与配置，FI／CO 与跨模块流程，ABAP／S/4HANA 技术，SAP × AI，最后整合业务流程、课程和 24 个月成长路线中依赖前述文章的导航内容。每批范围依据实际依赖图修订，不假定固定吞吐。

每批开始前，记录：

- 文章 ID、版本、场景、主张清单及直接来源／限定边界。
- 需要暂缓的主张、课程依赖和判断理由。
- 一个真实写作上下文；本批普通用户、资深 SAP 配置顾问、普通 SAP 开发人员三个独立角色上下文是否实际可用、其任务及当期容量。未落实时只产出未验收草稿，不将其标为完成。
- 批次提交点、出错回退方法、可恢复检查点与 handoff 更新。

若遇到无直接依据的技术事实，不以模糊限定掩盖；收窄、删除、标为知识缺口或暂缓核心文章。通常的一般知识正文不要求 SAP 实机测试；只有声明目标系统行为、特定配置、权限、数据、性能、账务结果或代码运行结果时，才要求对应版本／环境证据或明确标为待验证。

## 4. 五项未闭合阻碍的限制

| 项目 | 允许的建设边界 | 当前必须暂缓的范围 |
| --- | --- | --- |
| FI-07 | 按直接来源明示的版本和特殊场景写 GR/IR 或 MAP 例子，并说明例子限制。 | 普通估价库存采购的通用完整借贷分录、税、OBYC 账户映射／配置和未裁决的冲突结论。 |
| PROCESS-01 | 写来源实际支持的阶段概念或单个 SAP 2021 功能，分别标注版本／场景。 | 通用 P2P 全链逐笔分录、争议中的 GR/IR 方向、完整税／配置／异常及从 payment media 推断银行付款成功。 |
| MM-09 | 写 2021 原文实际支持的 GR/IR 概念及有限科目确定输入因素。 | 普通估价库存收货的确定方向、BSX／WRX／OBYC 全规则、配置路径或权限，直到证据闭合。 |
| ABAP-02 | 写有证据限定的 ABAP 7.56 语义与 ABAP Platform 2021 诊断材料，标明版本差异和目标环境验证项。 | 通用内存安全阈值、TRY...CATCH 可提前捕获并停止 warning dump、保证避免 dump 的生产方案。 |
| ABAP-04 | 写一般调用方 LUW、commit／rollback 与 update process 概念，不声称等同特定 BAPI 合同。 | BAPI_PO_CREATE1 函数级提交／回滚、WAIT、RETURN 处理和失败合同、RFC 边界或可复制的目标版调用代码。 |

若这些内容是文章的核心教学目标，则相应文章应保持“暂缓核心”；若文章可明确分离出有依据的概念部分，可按“限缩可写”形成正文，但未证核心章节不计作正式完成。以上边界以本次评估记录和既有来源档案为准，不代表新来源核验。

## 5. 保留的质量标准

- 目标主版本仍为 SAP S/4HANA 2021 On-Premise；ECC 只作必要差异说明；FI／CO 从零开始。
- 文章以业务原因、流程、配置、T-Code、数据模型和跨模块联系解释，不只列事务码。
- 采用普通用户、资深 SAP 配置顾问、普通 SAP 开发人员三个真实审核角色。每篇每角色按需 5～10 个有效闭环，每篇合计 15～30 个；每个闭环包含问题、Work 依据性答复、修订判断和该角色复核。没有真实独立上下文时如实披露，不能冒充。
- 10 轮后仍有阻断／严重缺陷时继续修复与复验，未解决不得通过；不能因达到轮数自动放行。
- 正式文章完成数量、有效文章审核闭环和 SAP 实机验证分别统计，不混计目录、来源登记、结构审查或计划复核。当前仍是 0 篇、0 轮、未连接 SAP。
- M4 和最终 M5／PR 验收仍按所有者审批；PR #20 不自动合并。
