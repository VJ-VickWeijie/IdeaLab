# CareerOS V0.3｜M0 阶段评审与 M1–M3 预案

状态：**M0 已获项目所有者批准；允许准备 M1–M3 联合评审材料；M1–M3 尚未获批，M4 未授权。** 本文和覆盖矩阵是阶段审阅材料，不是正式知识库或最终验收。

## M0：目标、对象和边界

- 学习者是已有 ABAP 开发经验、需要从零补齐业务与 FI/CO 基础的 SAP 从业者。中文讲解并保留英文术语，以 S/4HANA 2021 为目标版本，ECC 仅必要对照。
- 覆盖 MM、SD、PP、QM、FI、CO、ABAP、S/4HANA、AI 集成；按业务理由、角色、业务流、单据、物流、会计、实现、配置和技术关联组织。保留原有 24 个月路线和家庭/工作边界。
- 碎片阅读入口建议为“从一笔购买开始”，每篇有概览、先修、预计阅读时间，再分段讲解。财务先解释会计等式与借贷，后进入 GR/IR 与成本；练习可选，允许纯阅读和虚构数据。
- 导航优先中文；缩写首次出现提供中英文全称、通俗释义及示例，维护统一术语表和互链。长篇设 3–5 分钟概览及回链；正文附理解检查与基于原文的答案，提供无需 SAP 系统的可选虚构数据练习。阅读理解由模拟读者检查不等于真实用户实测。
- 仅使用公开资料及虚构案例；未经授权不使用企业数据或修改生产配置。SAP 操作标识阅读、只读查看、需额外授权；资料核验与实际系统测试分开。
- 完成意味着批准范围内的文章和课程均达到证据、导航、三个角色逐篇审核及严重问题关闭的标准；不宣称覆盖整个 SAP 产品。

## M1：多角色评审预案

方案 A：按模块集中组织，流程重复写入多个模块。缺点是跨模块不易连贯、内容易不一致。

方案 B：按统一业务流程组织唯一主文，模块目录维护基础/功能/T-Code/配置/数据模型，再链接流程；课程只引用原文。**建议 B**，与已确认知识树一致。风险是文章及引用较多，需冻结文章定义并维护链接、版本和审核状态。

已收到真实独立执行上下文的读者、配置顾问、开发者蓝图初评；详见[阶段独立初评记录](../reviews/work/preflight-independent-feedback-v0.3.md)。本次意见不计正式文章轮次，不等同真人用户或持证顾问验收。

## M2：专业设计预案

1. 各模块按现有知识树保留五类栏目；配置文章与事务索引互链。单一权威流程文章可含概览和分节，避免重复全文。
2. 每篇写清产品/发行版/FPS 或未能确认之处，来源优先可定位 2021 On-Premise 或相应 ABAP Platform 文档。最新版、云版或较早文档只能作为线索，不直接证明 2021 适用。
3. 所有场景明确前提，至少区分库存和消耗采购、估价与非估价收货、发票次序、STO 同公司与跨公司和开票条件、生产确认/结算、质量使用决策与库存过账的关系。会计案例列假设、金额、借贷和触发事件；税务及币种按区域与配置注明限制。
   端到端示例分别标出角色、事件、单据、实物、会计及资金，各流可能不发生变化；不得将收货、发票与付款混为一谈。财务顺序为会计等式和账户类别、借贷、总账、应收应付，之后再涉及 GR/IR 及成本。
4. 区分业务对象、物理表、兼容视图及发布 API，列键、关联、授权和适用版本。不能把最新版 ABAP Cloud 或 RAP 功能直接视为 2021 可用。技术或其他文章中不适用的物流、会计等要求，标注不适用和原因。
   BAPI 分别核验 LUW、提交/回滚以及个别 API 的事务例外；事务码可见不代表有权操作或已做系统验证。
5. 每篇 3 角色各 20 个不同、完整闭环：问题→依据及 Work 答复→修改或不修改的理由与版本→同角色复核。记录 `article_id`、`role`、`round`、`question`、`evidence`、`work_response`、`change_ref`、`recheck`、`status`、`executor_context`、`timestamp`，以 `(article_id, role, round)` 为唯一键并关联精确文章版本；未完成或无实质内容不计数。正式内容修改后判断原复核是否仍有效。

## M3：实施规划预案

M0 评审时提出 98 篇候选文章（至少 5,880 个闭环），后续因统一术语表未单列而增加候选条目；当前数量以[覆盖矩阵提案](coverage-matrix-v0.3-proposal.md)为准。导航及课程候选条目暂按正式文章同等门槛核算；变更文章粒度或要求须记录并获适用授权。此数量是计划估计，不是已完成成果，也不是质量保证。

| 工作包 | 输入/依赖 | 负责人 | 完成与验证 |
| --- | --- | --- | --- |
| M0 目标审阅 | 本文、项目原记录 | 所有者决策；协调者准备 | 目标、边界、成功标准明确，记录批准版本 |
| M1 方案评审 | M0 批准；已有三角色初评 | 协调者与独立角色 | 比较方案、反对意见与证据；记录待解决问题 |
| M2 知识设计 | M1 批准或经所有者同意合并审批点 | 协调者、领域审查者 | 文章模板、版本与场景边界、知识链接及证据标准 |
| M3 范围与任务 | M2 批准或经所有者同意合并审批点 | 协调者、审查者 | 冻结文章清单、验收和审核资源安排，形成 M4 请求 |
| M4 正文建设 | 明确 M4 批准 | 作者/协调者 | 写作、依据核对、真实三角色逐篇往返和版本记录；分批可恢复提交 |
| M5 审查验收 | 满足获批的阶段转换要求 | 独立审查者 | 检查原始轮次、文章版本、严重缺陷、覆盖与测试，不满足即返工 |
| M6 交付 | 必要验收与批准 | 协调者 | 更新真实 README，提交 PR；用户最终决定，不自动合并 |

阶段可在所有者批准时合并审批点，仍保留各阶段成果及审查证据。发生工作量或执行环境限制时记录真实进度与阻碍；不能承诺后台自动继续或把半成品当成完整交付。初期按 FI 基础、MM/QM、P2P 优先，之后 SD/PP、STO、R2R、技术、AI 和课程。正式编写前在矩阵补充每篇预期路径、证据、场景和审核状态；实际增删文章需追踪分母及影响。

M3 的强制退出成果须将当前概括性矩阵细化到每篇：目标路径、前提、最小场景和例外、依赖、具体可访问的来源与版本、验证方式。流程主文逐项映射单据/货权/在途/价值和资金影响及不适用原因；配置项映射业务行为、只读入口与前提。一般 AI 架构和 SAP 2021 接口使用各自适用的证据，不能错误地要求所有通用 AI 概念都有 2021 SAP 文档。版本未核实的主张阻止正式文章进入 reviewed/accepted，系统验证未做时另行披露。

## 验证计划与缺陷处理

- 执行相对链接、目标文件、大小写、锚点、重复 ID、孤立导航和外链检查；分别报告失败、未检查和通过。以实际仓库版本为验证对象。
- 汇总矩阵分母、正文完成、每角色有效轮次及独立上下文、严重缺陷与复验状态。阻断性问题暂停相关推进；严重问题修复并复核；未经实机验证的事务/配置标明限制。
- 可创建真实独立子代理上下文；本次未手动切换模型，实际模型标识不可确认。独立上下文不代表真实终端用户、资深认证顾问或多模型，也不能保证正确性。
