## 交付范围
依据 `architecture/knowledge-tree-v0.3.md` 建立模块知识库、统一业务流程库、课程导航；Work 自主拆分可完成的 V0.3 细粒度文章清单并建立覆盖矩阵，列明每篇预期深度、验证方法和完成定义。不得以空目录、标题或少量样板冒充全部交付。

所有文章中文为主、英文 SAP 术语并列，先讲业务原因与基础概念，再讲端到端流程、单据、物流/价值流、系统实现、配置、T-Code、数据表、异常和跨模块关联。FI/CO 面向完全零基础；版本以 S/4HANA 2021 为主要基准，注明 ECC 与配置差异。课程引用文章而非复制内容，练习可选且适合只读权限。

## Work 与三角色循环
Work 为主执行者；必须组织：
1. 普通用户（零基础阅读者）
2. 资深 SAP 配置顾问
3. 普通 SAP 开发人员

**每个角色对每篇正式文章按需进行 5～10 个有效质询—答辩—修订—复核轮次**，合计每篇 15～30 轮；详见 `reviews/README.md`。尽可能采用真实独立上下文/子代理；如不支持，透明披露，不能虚构。持续修订至阻断/严重缺陷关闭，保留真实记录、版本差异和证据。为控制工作量，应分批提交可追溯进度，但最终以完整范围验收为准；5～10 轮不是机械凑数，也不保证绝对正确。

## 验收门槛
- 完整目录与细粒度覆盖矩阵；计划与完成严格区分。
- 范围内每篇文章内容完整，有可追溯来源和适用条件。
- 每篇三角色分别按需 5～10 个有效轮次，有问题、回答、修订、复验记录；独立性状态明确。
- 无阻断/严重未解决错误；Markdown 链接与导航可检查。
- 所有 SAP 系统操作依权限区分“阅读 / 只读 / 需授权”，不得要求改生产配置。
- 原有 24 个月职业规划保留，课程链接知识库。
- GitHub 保留 Work 日志、角色记录、覆盖率、缺陷、测试证据与限制。
- 最终以 PR 提交，**不自动合并**；用户审查后才决定下一阶段。
