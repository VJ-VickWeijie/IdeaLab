## 区分知识关联与硬依赖

三个细化文档中每行“依赖”或“前置与内容”列含跨主题**知识关联**；它本身不是阻止创建草稿或需要先验收另一文章的硬依赖。互链可双向，例如 MM-01/MM-02、PP-02/PP-03、FI-11/S4HANA-09、ABAP-02/S4HANA-02。关联文章可同批拟稿和统一确认术语，不能因此认定课程零基础读者已读过另一文章。具体阅读先修按课程方案排序；入口允许先读独立概览，再于后续学习完整流程。

真正的执行硬门禁是工作包，而非强制每篇文章的线性拓扑：

1. M0 已批准 → 完成 M1–M3 提案和缺陷清单 → 明确取得 M4 范围和执行授权。
2. 获 M4 授权后，各领域可并行草拟、定位来源和创建待审稿；并行工作由单一作者串行整合每篇文章。来源或版次缺失的主张保持待核，相关文章不能进入 reviewed/accepted。
3. 在文章 A 的待审版本可读且来源证据可追溯后，组织三角色提出问题、答复、修订和复核；相关联文章可同时在建，但文章中未建目标不能标记为已验证链接。
4. 只有文章自身全部要求与三个角色各 5～10 个真实有效闭环完成、严重缺陷关闭，才可标 reviewed；accepted 另依所有者授权的质量与独立验收门槛。
5. 各候选正文和导航齐备后做全库链接与覆盖验证；M4 转入 M5 前须由所有者明确批准，或由所有者事先明确批准合并 M4/M5 审批点且保留独立审查证据。随后独立验收并由用户最终决定。上游条目变更影响已审文章时必须评估并重审相关断言。

这组工作包的硬依赖图为 `M0 → M1–M3 提案/审批 → M4授权 → 草拟与查证 → 三角色审查 → 全库验证 → M4/M5 所有者审批点（或事先批准合并）→ 独立验收 → 用户最终决定`。三份领域表仍需将字段标题调整为“关联”，不将这些关联伪装成无环先修图。

## 资料不足与回退

每篇至少定位具体来源、可访问状态、目标产品和版本以及对应主张；必须区分搜索可见、正文可读、版本适配及实际支持某一具体主张四个状态。搜索摘要、通用产品首页和新版文档均不能直接支持 2021 事实。公开来源不可用时先尝试同一官方内容其他固定版本、官方 PDF、明确有效的官方帮助/版本说明；仍无法取证则记录标题、URL、尝试日期和缺口，保留“未核验”，该文章停在未通过状态，不借用另一篇证据充数。实机权限独立记录：仅文献可核验的项可记“资料核验通过、实机未测”；要求系统实测的断言不得标为实测通过。

当前逐篇材料仍主要是文档入口和研究线索，物流部分 Fiori 更新页、财务 F3–F8 和技术部分网页存在版本/正文未确认情形；故**未满足原 M3 逐篇具体可访问资料与版本的退出要求**。不得因为条目齐全就宣称该门槛已通过或 M4 已授权。用户可先评审范围及方案，随后需要补足证据或明确处理已记录阻碍。
