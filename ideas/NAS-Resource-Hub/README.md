# NAS 资源订阅与自动下载中心

## 灵感卡

- **一句话想法**｜在已有绿联 NAS 的 Docker 环境中搭建一个资源订阅与下载中心，定时关注指定站点的新资源，发送通知，并按预设规则自动启动下载任务。
- **灵感起点**｜NAS 已安装 Docker，希望减少手动登录资源站点、逐个检查更新和手动下发下载任务的重复操作。
- **最想保留的点**｜「资源更新发现 → 通知用户 → 符合规则时自动下载」的完整闭环，并能统一调用 NAS 上的下载工具。
- **当前状态**｜灵感（AI-Workflow M0 目标探索入口；尚未批准调研、验证或开发）
- **下次打开时**｜确认目标站点是 PT 还是语音中提到的“PD”，明确想监控的资源、通知渠道，以及自动下载是否需要人工确认。

## 初步使用场景（构想，尚未确认需求）

1. 用户在 NAS 中通过 Docker 运行下载客户端（一个或多个，尚未选型）。
2. 订阅中心按约定时间检查用户有权限访问的资源站点，识别关注类别或条件下的新资源。
3. 发现新资源后，以邮件或其他方式向用户推送更新摘要。
4. 对符合用户预设条件、且站点许可自动化下载的资源，向下载客户端发起任务；不满足条件的资源仅通知并等待用户操作。
5. 后续可在 NAS 上查看任务是否已下发、下载进度、失败记录及存储空间占用。

> 以上 4、5 点属于功能方向的补充整理，并非用户已确认的规格。具体是否需要人工审批、监控频率、界面和下载管理能力均待讨论。

## 已知环境与约束

- NAS：绿联 DXP4800；已安装 Docker；用户希望优先考虑 NAS 上的容器化运行与管理。
- NAS 内存 8GB，无独显；优先轻量级服务，不安排本地 AI 推理。
- 磁盘空间相对充足，但后续仍需评估下载目录、容量告警、上传分享率和网络占用。
- 既有自有域名，但外网访问方式未确认；此创意没有提出必须公网开放管理页面。
- 用户以前讨论过 PT 站点，因此暂按 **PT** 理解本次语音提到的“PD”；这一术语仍需用户核实。
- 只监控用户有合法访问权的站点与内容；应遵守站点规则，不绕过认证、反自动化措施或分享率要求。
- 密码、Cookie、下载器凭据不得存入公开 GitHub 仓库；优先最小权限、密钥隔离、内部网络访问。
- 站点允许的订阅／自动化方式及个人数据、版权合规须在实施前确认。

## 待明确的问题

1. 目标网站类型：PT 还是其他“PD”网站？哪些站点允许订阅或自动化操作？
2. 资源范围：电影、动漫、剧集，还是其他类型？是否沿用先前 PT 资源整理的思路？
3. 自动下载规则：完全自动、仅提醒手动确认，还是两种模式并存？过滤条件和重复资源如何判定？
4. 现有下载客户端：qBittorrent、Transmission、Aria2，或尚未安装？是否需要本项目负责启动／停止容器？
5. 通知：邮件、企业微信、Telegram 或其他；频率、即时性与失败告警要求？
6. 资源保存：下载目录、命名、分类及后续媒体库/刮削系统是否需要衔接？
7. 负载与安全：检查频率、站点限速、分享率维护、NAS 8GB 内存与存储保留策略？
