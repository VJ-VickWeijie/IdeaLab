## 2. 每次接手的强制顺序

`IdeaLab README + AGENTS → 目标项目资料 → AI-Workflow 固定版本 → 当前里程碑和授权 → 动态组队 → 阶段执行 → 审查 → 用户审批`。

无论是新项目、继续项目、换工具、换会话还是开始新主要阶段，都需要重新检查相关文件是否已变化。

## 3. 七阶段通用生命周期

| 阶段 | 目标 | 阶段成果 |
| --- | --- | --- |
| M0 | 需求/目标探索 | 目标、范围、约束 |
| M1 | 多角色评审与批判 | 备选方案、反对意见、推荐与待验证假设 |
| M2 | 专业方案设计 | 架构、剧本、研究方案等项目专用成果 |
| M3 | 任务拆解与规划 | 依赖、负责人、验收标准、执行计划 |
| M4 | 授权范围内自主执行 | 实际成果、测试/实验记录 |
| M5 | 独立审查与验收 | 证据、缺陷、修复结果、遗留风险 |
| M6 | 交付与复盘 | 交付链接、经验、下一轮建议 |

阶段可按项目规模合并或拆分，但主要里程碑必须获得用户批准才能跨越。

## 4. AI Team 运行约定

- 固定职责：协调、规划、批判、审查；动态专业角色按领域和阶段分配。
- 关键争议：先独立提出方案，再交叉质疑、必要时验证证据，最后形成可追溯推荐；不强求虚假共识。
- 阶段自治：在既定目标、成本、权限与范围内选择 Skills、工具与角色，自行执行和返工。
- 任务审查：自检与独立审查分开；无法真正隔离审查者时明确标注。
- 回退规则：普通缺陷退回执行；设计缺陷退回设计；重大需求冲突暂停并请求用户确认。
- 里程碑报告：目标、成果、争议、验证证据、风险、下一阶段建议；用户可批准、要求重审、暂停或终止。

## 5. 接入和版本规则

项目文档中的已批准固定 SHA 优先。没有项目级锁定时使用本页默认固定 SHA。新模板和项目交接应记录实际解析出的 SHA、当前里程碑和最后批准的决定。升级须检查兼容性及授权。V1.1 候选包含按任务难度、风险、环境能力与预算选择模型的规则。只有候选合并并经项目批准采用后，子项目才按该版本规则选型；不同环境若不支持按角色切换模型，应记录限制和实际使用模型。

工作流版本无法读取时，记录缺失并暂停依赖该规范的阶段执行；可保留只读核查。记录实际可用的工具与 Skills。

## 6. Work / Codex 交接

- Work 适合目标探索、需求讨论、方案比较、协调和里程碑汇报。
- Codex 适合检查真实代码、实现、测试和代码级审查。
- 两者通过 GitHub 中已批准的项目资料、Issue、PR、交接记录协作，不假设可自动互相唤醒。
- 角色与工具必须根据项目类型选择；非软件项目不强制生成 PRD 或代码。
- 定时跨项目监督是可选外部机制，不是每个里程碑的必经节点。
